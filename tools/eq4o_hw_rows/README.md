# eq4o_hw_rows — real-hardware row-shift fixtures and measurement

Fixtures and a deterministic analyser for the EQ-4o real-hardware run that
tests the EQ-4n hypothesis (B): the one-capture-row shift seen in our Azahar
host render is introduced by the core's presentation readback, not by the
arm11 program or PICA. Result and full evidence:
`docs/reports/eq4o-hw-row-shift.md`.

**Scope of the evidence:** one New 3DS console, one capture session per frame,
one `arm11/twlhd-arm11.3dsx` build (not rebuilt for this task). No claim here
generalises to other consoles, sessions or geometry.

## 1. Files

| Path | Purpose |
|---|---|
| `hw_frameA_top400x240.png` | frame A (EQ-4n frame) 400×240 top-left crop |
| `hw_frameB_top400x240.png` | frame B (frame A with every vertex y +3 DS px) |
| `measure_rows.py` | white runs, edge table, row 0/239 and row 120 probes |
| `test_measure_rows.py` | synthetic nominal/+1/frame-B tests and fixture FACTs |
| `README.md` | this file |

Neither fixture is generated by the repository. They are the owner's crops of
the top screen of a 1280×720 passive capture; the arm11 render is 400×240, so
the top-left 400×240 crop maps 1:1 and a capture row is a render row.

## 3. Usage

```
$ python3 tools/eq4o_hw_rows/measure_rows.py tools/eq4o_hw_rows/hw_frameA_top400x240.png
$ python3 tools/eq4o_hw_rows/measure_rows.py --dy 3 tools/eq4o_hw_rows/hw_frameB_top400x240.png
```

`--column N` (repeatable, default 100) selects the column for the white-run
and row probes; `--dy D` shifts the nominal DS geometry (0 for frame A, 3 for
frame B). Exit 0 on success, 2 on usage or input errors.

White means `(R+G+B)/3 >= 128`. The clear colour of these captures is
`(16,16,24)`.

The edge table uses the EQ-4n §3.3 DS geometry: `top_band.bottom` y=16,
`sq1.top` 32, `sq1.bottom` 64, `sq3.top` 128, `sq3.bottom` 160,
`bottom_band.top` 176. Nominal capture row is `1.25 * (y_ds + dy)`. The
measured row is the actual state transition: for a `*.top` edge the first white
row whose row above is dark, for a `*.bottom` edge the first dark row whose row
above is white, scanning `ceil(nominal)-3 .. ceil(nominal)+3` (clamped to
`0..239`). Row 0 counts as a transition when already in the target state (no
row above); no transition in the window yields `measured=none`, `match=other`.

## 4. Expected fixture output (EQ-4o FACT)

Measured with HEAD `d18a9b9`.

Frame A, column 100: `white_runs=0-19,40-79,160-199,220-239`; rows 0..2 white;
every edge `measured == ceil` (20, 40, 80, 160, 200, 220).

Frame B (`--dy 3`), column 100: `white_runs=4-23,44-83,164-203,224-239`; rows
0..2 dark `(16,16,24)`; every edge `measured == ceil` (24, 44, 84, 164, 204,
224).

Both frames: row 120 first/last white columns 40 and 359, black at 39/360, and
`row0_wrap=0`.

## 5. Tests

```
$ make test-eq4o-hw-rows
```

The synthetic tests include the negative case: the whole scene moved one extra
capture row must be reported as `match=ceil+1` on every edge. The target is
wired into `make test` the same way as `tools/ds_edge_test`.
